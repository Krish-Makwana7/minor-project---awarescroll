All buttons: 44px minimum tap target, disabled state at 40% opacity, 150ms ease-out press scale (0.97).
Inputs
Fields use a 12px-radius box, 1.5px Border (#E2E4F0), 16px internal padding, Primary-colored 2px focus ring. Error state swaps the border to Error red and shows inline helper text below in Error red, Caption size. Goal-setting inputs (e.g. "minutes per day") use a stepper control, not free text, to keep intention data structured.
Cards
Surface background, 16px radius, 1px Border, 1-level soft shadow (0 2px 8px rgba(20,21,43,0.06)), 20px internal padding. Three card types:
Insight card — used on the dashboard for a single pattern/recommendation; icon + H3 title + Body Small description + optional small chart.
Session card — used in history lists; shows intention vs. actual duration as a small horizontal bar, task/app icon, timestamp.
Stat card — Stat/Timer type front and center, Stat Label beneath, minimal chrome.
Modals / Sheets
Two patterns:
Reflection modal (AwareScroll) — bottom sheet, non-full-screen, Accent-tinted header strip, short feedback questions (single-tap chips, not free text, wherever possible), two buttons (Reflect-style above).
FocusLock restriction sheet — full-screen, Background Dark regardless of system theme (reinforces "you're in a session"), large Stat/Timer countdown, single Destructive "End session" button requiring a confirmation step (tap-and-hold or type-to-confirm) so exits are deliberate, not accidental.
All modals use a 200ms ease-in-out slide/fade, dismiss via explicit button only (no swipe-to-dismiss on FocusLock sheets, to preserve the restriction's intent).

Note on platform limits: neither iOS nor Android lets a third-party app fully block another app or guarantee precise foreground-time tracking without the user granting Screen Time / Usage Access permissions, and iOS in particular restricts what Family Controls exposes to non-parental apps. The frontend must handle a "permission not granted" state gracefully (degrade to manual check-ins) rather than assume monitoring always works.
1. Firebase Auth
Endpoints called via Firebase SDK (not raw REST): signInWithEmailAndPassword, createUserWithEmailAndPassword, signOut, onAuthStateChanged listener. Sends: email, password (or OAuth token). Returns: User object with uid, used as the foreign key on every record below.

4. iOS Screen Time API
Frontend calls AuthorizationCenter.shared.requestAuthorization() once, then sets DeviceActivitySchedule + DeviceActivityEvent thresholds for Instagram's bundle id. On threshold, the system delivers a DeviceActivityMonitor callback the app uses to trigger the in-app reflection modal — this is OS-driven, not a network call.
5. Android Usage Access
Frontend requests PACKAGE_USAGE_STATS permission, polls UsageStatsManager.queryEvents() for Instagram foreground/background events, and uses an AccessibilityService (optional, user-opted) to detect and soft-block app switches during an active FocusLock session.
6. Firebase Cloud Messaging
Backend (Engine or a Cloud Function) sends a push when a predicted risk score crosses a threshold or a scheduled check-in is due. Payload: {type: "reflection_reminder"|"checkin", uid, sessionId?}. Frontend's notification handler routes the tap to the matching screen.
7. Firebase Storage (work evidence)
Frontend uploads via uploadBytes(ref(storage, 'evidence/{uid}/{sessionId}.jpg'), file). Returns a storage path saved onto the session record. The UI must label this as supporting evidence only, consistent with the product's own framing that an image can't fully verify task completion.
